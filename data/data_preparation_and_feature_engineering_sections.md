# Data Preparation

The data preparation process integrated the O*NET 30.3 database with the May 2025 Occupational Employment and Wage Statistics (OEWS) All Data file from the U.S. Bureau of Labor Statistics. The raw source archives were preserved without modification, and all transformations were performed through a reproducible Python workflow. The O*NET release contained 1,016 distinct occupations, while the filtered BLS file contained 830 national, cross-industry, detailed occupations.

Column names were standardized to lowercase snake-case formatting, leading and trailing whitespace was removed from identifiers, and numeric fields were converted to numeric data types with invalid entries treated as missing. The complete O*NET-SOC code was retained as the occupation-level identifier. Because O*NET includes detailed extensions such as `11-1011.03`, while BLS generally reports the corresponding six-digit SOC code such as `11-1011`, a separate six-digit `soc_code` field was derived from the O*NET identifier. This field served as the controlled bridge between the two sources without removing the more detailed O*NET code.

The O*NET Occupation Data table was used as the base table because it contains one record per occupation. Supporting O*NET tables for essential skills, transferable skills, knowledge, abilities, work activities, work styles, career interests, job zones, and education were cleaned separately. Tables containing multiple measurements per occupation were reshaped from long to wide format. For essential skills, transferable skills, knowledge, abilities, and work activities, importance and level scores were retained. Career interests were reshaped into the six RIASEC dimensions, and work-style impact measures were reshaped into occupation-level columns. Job zone information was merged directly because it was already recorded at one row per occupation.

Missing values were not filled automatically. Records were preserved when the absence of a field reflected unavailable source information rather than an invalid occupation. Essential occupation identifiers were complete, and the base occupation table contained no duplicate O*NET-SOC codes. Suppression flags in O*NET rating tables were respected by excluding measurements marked for recommended suppression. BLS symbols and nonnumeric wage or employment entries were converted to missing values instead of being assigned unsupported estimates.

The BLS dataset was filtered to national U.S. estimates, cross-industry coverage, combined ownership, and detailed occupation rows. This produced 830 unique BLS SOC codes. The O*NET master table was then left-joined to the BLS table using the six-digit SOC code in a validated many-to-one merge. The left join preserved all 1,016 O*NET occupations. A total of 961 O*NET occupations matched a BLS record, producing a 94.6% match rate, while 55 occupations remained unmatched. These unmatched occupations were retained in a separate review file rather than silently removed.

Data quality and consistency checks confirmed that the final dataset contained 1,016 unique O*NET occupations and 408 variables. No duplicate full O*NET-SOC codes, negative employment values, or negative annual median wage values were identified. Row counts were checked after every merge to prevent accidental many-to-many expansion. Separate reports were generated for missing values, unmatched occupations, feature definitions, and overall data quality.

# Feature Engineering

Feature engineering was designed to support interpretable career matching and labor-market comparison. The final features represent occupational requirements, personal-interest alignment, preparation requirements, and current labor-market opportunity. O*NET rating tables were transformed into occupation-level columns so that each occupation could be compared across individual skills, knowledge areas, abilities, work activities, work styles, and interests.

For each major O*NET domain, summary measures were created in addition to the individual ratings. These included mean and maximum importance scores and, where available, mean and maximum level scores. These summary variables provide compact representations of the overall intensity of each occupational domain while retaining the original component-level features for more detailed matching.

The six RIASEC career-interest scores were retained, and three additional features were engineered: the dominant interest type, the highest interest score, and the range between the highest and lowest interest scores. The dominant-interest feature supports clear interpretation of the occupation’s primary interest orientation, while the score range indicates how specialized or broadly distributed the interest profile is.

Education responses were summarized using the O*NET required-level-of-education categories. An expected education category was calculated as a weighted average of category values using the reported response percentages. The modal education category was also retained, along with the percentage of responses indicating a bachelor’s degree or higher. Job zone was included as a separate indicator of the overall preparation, education, experience, and training typically required for the occupation.

Labor-market features were derived from the May 2025 BLS estimates. Total employment was transformed using `log1p` to reduce the influence of extremely large occupations while preserving occupational ordering. Annual wage dispersion was represented by the difference between the 90th and 10th percentiles and by the interquartile range. A median-to-mean wage ratio was created to indicate wage-distribution asymmetry. Percentile ranks were calculated for annual median wage and total employment, and their mean was used as a transparent labor-market opportunity score. This score is descriptive rather than predictive and gives equal weight to compensation and employment scale. The project does not label it as future job growth because the OEWS source contains current employment and wage estimates rather than employment projections.

Variables were retained when they contributed to occupation identification, user-to-career matching, preparation requirements, or labor-market interpretation. Full and six-digit SOC codes, occupation titles, descriptions, and BLS titles were retained for identification and display but should not be used as ordinary numeric predictors. Individual O*NET ratings, RIASEC scores, job zone, education summaries, wages, and employment measures were retained as candidate recommendation features. Administrative fields, sampling statistics, confidence-interval bounds, source dates, domain-source labels, and duplicate title fields from supporting O*NET tables were removed from the modeling dataset because they describe data collection rather than occupational characteristics. Raw suppression indicators were used during cleaning but were not retained as recommendation features.

Data leakage prevention will be applied before any supervised model evaluation. Occupation identifiers and display text will be separated from the numeric feature matrix unless text is intentionally modeled in a documented pipeline. Any imputation, scaling, encoding, dimensionality reduction, feature selection, or weighting learned from data will be fitted on the training set only and then applied to validation and test sets. If multiple records are later created for the same occupation, splitting will be grouped by O*NET-SOC code so the same occupation cannot appear in both training and testing data. Current BLS variables may be used as descriptive recommendation criteria, but variables derived from a target outcome will not be used to predict that same outcome.

# Feature Selection and Removal Summary

| Variable group | Decision | Justification |
|---|---|---|
| Full O*NET-SOC code | Retained for identification | Preserves detailed occupation identity and supports auditing. |
| Six-digit SOC code | Retained as merge key | Provides a consistent bridge between O*NET and BLS. |
| Occupation title and description | Retained for display; excluded from ordinary numeric modeling | Required to explain recommendations but can function as identifiers. |
| O*NET skills, knowledge, abilities, activities, interests, and work styles | Retained | Directly support user-to-occupation matching. |
| Job zone and education summaries | Retained | Represent typical preparation requirements. |
| BLS employment and wage measures | Retained | Represent current labor-market scale and compensation. |
| Sampling errors and confidence bounds | Removed from recommendation features | Describe estimate uncertainty rather than occupation characteristics. |
| O*NET source dates and domain-source labels | Removed from recommendation features | Administrative metadata with no direct matching value. |
| Duplicate titles from supporting tables | Removed | Redundant with the base occupation title. |
| Suppressed O*NET measurements | Excluded | O*NET recommends that these values not be reported or used. |
| Future growth features | Not created from OEWS | The downloaded OEWS file does not contain employment projections; creating growth values would be unsupported. |
